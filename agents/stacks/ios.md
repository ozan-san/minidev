# iOS / Swift

## All roles

This is a Swift project: an Xcode app (`.xcodeproj`/`.xcworkspace`, possibly generated by XcodeGen/Tuist) or a Swift Package (`Package.swift`).

- Build/test with `xcodebuild` (apps) or `swift build`/`swift test` (packages). Always pass `-quiet` and `CODE_SIGNING_ALLOWED=NO`, and pipe through `tail -n 80`. The exact commands are in your task.
- **Project file membership is the #1 failure mode.** A new `.swift` file in an Xcode project only compiles if it belongs to a target:
  - Xcode 16 *synchronized folders* (`PBXFileSystemSynchronizedRootGroup` in `project.pbxproj`) and Swift Packages (`Sources/<Target>/`) pick up new files automatically.
  - XcodeGen (`project.yml`) / Tuist (`Project.swift`): files are found by the manifest's source globs; edit the manifest if needed, never the generated `.xcodeproj`.
  - Classic groups: the file must be registered in `project.pbxproj` (`PBXFileReference`, `PBXBuildFile`, the group's `children`, and the target's `PBXSourcesBuildPhase`) with unique 24-hex-char IDs. Prefer adding code to existing files when that is reasonable; when a new file is needed, copy an existing entry exactly.
- Never edit `.pbxproj` merge-conflict style or reorder unrelated entries; never touch signing settings, provisioning or team IDs.
- Localization: use the project's mechanism (String Catalog `.xcstrings`, `Localizable.strings`, SwiftGen `L10n`, `String(localized:)`); never hard-code user-facing text.
- Don't leave simulators booted or apps running.

## Scout

Map: targets and schemes, app vs extensions vs frameworks/packages, local Swift packages, dependency manager (SPM, CocoaPods, Carthage), project generation (XcodeGen/Tuist), whether the project uses synchronized folders (`grep -c PBXFileSystemSynchronizedRootGroup *.xcodeproj/project.pbxproj`).
Identify UI (SwiftUI vs UIKit/storyboards), architecture (MVVM, TCA, VIPER, coordinators), concurrency (async/await + actors vs Combine vs callbacks), DI, networking, persistence (SwiftData/Core Data/GRDB/Realm), localization approach.
Tests: test targets, XCTest vs Swift Testing (`import Testing`, `@Test`, `#expect`), snapshot testing, `@testable import` module names.
Commands: scheme + destination used in CI (fastlane `Fastfile`, workflows), SwiftLint/SwiftFormat config.

## Planner

- State per subtask *how new files get into the target* (synchronized folder, manifest glob, or explicit `project.pbxproj` registration).
- Keep each subtask building for the simulator; add types before their callers.
- Mark UI work that needs a manual check on a simulator/device in `manualChecks`.
- Info.plist changes (privacy usage descriptions, URL schemes, background modes) and entitlements are separate, explicit steps.
- Test plan: unit tests for view models, reducers, services, parsers, formatters — not UI tests.

## Builder

- Swift style: `let` over `var`, value types for models, `struct` views, `private` by default, `guard` for early exits, no force unwraps/`try!` in production code.
- Concurrency: UI state on `@MainActor`; `async`/`await` over completion handlers in new code if the codebase does; respect `Sendable` warnings; no `DispatchQueue.main.sync`.
- SwiftUI: `@State`/`@Binding`/`@Observable`/`@StateObject` as the codebase does; keep `#Preview`s compiling.
- UIKit: `[weak self]` in escaping closures that capture self; update UI on the main thread.
- Verify with the build command from your task; read `error:` lines first.

## Tester

- Put tests in the existing test target; ensure the test file is part of that target (same membership rules as above).
- Match the framework: XCTest (`XCTestCase`, `XCTAssert…`) or Swift Testing (`@Suite`, `@Test`, `#expect`); `@testable import <Module>`.
- Async code: `async` test functions; avoid `sleep` — use expectations/confirmations.
- Run only the relevant tests: `xcodebuild … test -only-testing:<TestTarget>/<TestClass>` or `swift test --filter <Name>`.

## Reviewer

iOS-specific blockers:
- Retain cycles (closures capturing `self` strongly in long-lived objects, delegates not `weak`).
- UI updates off the main actor; data races; blocking the main thread.
- Force unwraps / `try!` / `fatalError` on reachable paths.
- New files not added to the target (compiles only by accident?), edits to generated projects.
- Missing Info.plist privacy strings for new permissions; hard-coded user-facing strings; missing accessibility labels on icon buttons.
- Breaking public API of shared frameworks/packages.
